Використовуйте Git, щоб відстежувати зміни у плагінах, відкочувати помилки та обмінюватися кодом між машинами.

## Навіщо організовувати код?

Якщо у вас більше одного скрипта, узгоджена структура папок економить час і спрощує керування версіями.

## Структура папки з кодом

Один із найпростіших способів упорядкувати проєкти — створити окрему **папку code** на локальній машині. У ній можна створити підпапки для кожного проєкту або репозиторію. Ось рекомендована структура:

```plaintext
/home/your-username/code/
  ├── project1/
  ├── project2/
  └── project3/
```

Кожна підпапка (наприклад, `project1`) — це **репозиторій**, де зберігаються файли та код цього проєкту.

## Що таке репозиторій?

**Репозиторій** (або **repo**) — це папка, вміст якої відстежує Git. Коли ви ініціалізуєте Git у папці, будь-які зміни можна зберегти та синхронізувати з віддаленою копією.

### Локальні та віддалені репозиторії

- **Локальний репозиторій**: зберігається на вашому комп’ютері в одній із папок проєкту.
- **Віддалений репозиторій**: версія репозиторію в інтернеті (наприклад, на GitLab або GitHub).

## Використання Git і GitHub

Коли структура папок готова, ініціалізуйте Git і підключіть локальні проєкти до GitHub. Ось основні кроки:

### Основні кроки для Git і GitHub

1. **Встановіть Git**
2. **Створіть обліковий запис GitHub**
3. **Створіть порожній репозиторій на GitHub**
4. **Ініціалізуйте Git у локальному проєкті**
5. **Підключіть локальний repo до GitHub**
6. **Додайте файли до індексу**
7. **Зафіксуйте зміни (commit)**
8. **Надішліть зміни на GitHub (push)**
9. **Перегляньте репозиторій онлайн**

### 1. Встановіть Git

Якщо Git ще не встановлено, у Linux виконайте:

```sh
sudo apt install git
```

### 2. Створіть обліковий запис GitHub

Якщо облікового запису ще немає, зареєструйтеся на [GitHub](https://github.com/). Після реєстрації можна створювати репозиторії для зберігання коду онлайн.

### 3. Створіть порожній репозиторій на GitHub

1. **Увійдіть на GitHub**: перейдіть на [GitHub](https://github.com/) і увійдіть.
2. **Створіть новий репозиторій**:
   - Натисніть **+** у верхньому правому куті та виберіть **New repository**.
   - Введіть назву (наприклад, `your-repository`).
   - За бажанням додайте опис.
   - Виберіть **Public** або **Private**.
   - **Не** ініціалізуйте репозиторій README, `.gitignore` або ліцензією (щоб уникнути конфліктів).
   - Натисніть **Create repository**.

### 4. Ініціалізуйте Git у локальному проєкті

Щоб почати відстежувати папку проєкту, відкрийте термінал, перейдіть до неї та виконайте:

```sh
cd code/your/project/folder
git init
```

Ця команда ініціалізує порожній репозиторій Git у папці проєкту.

### 5. Підключіть локальний repo до GitHub

Після створення порожнього репозиторію на GitHub додайте його як remote:

```sh
cd code/your/project/folder
git remote add origin https://github.com/your-username/your-repository.git
```

Замініть `your-username` і `your-repository` на ваше ім’я користувача GitHub і назву репозиторію. Ця команда пов’язує локальний проєкт із віддаленим репозиторієм.

### 6. Додайте файли до індексу

Перед збереженням змін у Git потрібно вказати, які файли включити — це називається **staging**. Щоб додати всі змінені або нові файли:

```sh
git add .
```

Це каже Git відстежувати зміни у всіх файлах проєкту. Можна додати окремі файли, замінивши `.` на ім’я файлу.

### 7. Зафіксуйте зміни

Після staging наступний крок — **commit** у локальному репозиторії. Завжди додавайте повідомлення, що описує зміни:

```sh
git commit -m "Add new feature"
```

Прапорець `-m` дозволяє написати короткий опис змін для цього commit.

### 8. Надішліть зміни на GitHub

Після локального commit можна **push** на GitHub, щоб оновити віддалений репозиторій:

```sh
git push -u origin main
```

Гілка `main` — гілка за замовчуванням на GitHub; ця команда завантажує локальні зміни в remote.

### 9. Перегляньте код на GitHub

Після push можна переглянути репозиторій у веб-інтерфейсі GitHub — файли з локального repo та історію commit.

## Висновок

Організувавши код у окремих папках і використовуючи GitHub для керування та резервного копіювання, ви збережете проєкти структурованими та доступними. Маючи робочу версію коду, надішліть її на GitHub — потім легко відстежувати зміни через веб-інтерфейс GitHub або Visual Studio Code, який підсвічує змінені рядки. Так можна продовжувати вдосконалювати код, не втрачаючи прогрес.

Git і платформи на кшталт GitHub та GitLab — потужні інструменти; в інтернеті багато ресурсів для їх вивчення. Корисними бувають і ШІ-помічники на кшталт ChatGPT: опишіть мету — і вони покроково проведуть через процес.

## Глосарій

Поширені терміни при роботі з Git і GitHub:

- **Commit**: знімок змін у репозиторії. Кожен commit містить опис і створює запис в історії, до якого можна повернутися.
- **Репозиторій (repo)**: набір файлів та їхня історія, яку відстежує Git. Репозиторії бувають локальними або віддаленими (GitHub тощо). Зазвичай кожен проєкт має свій repo.
- **Remote**: віддалена копія проєкту на платформі на кшталт GitHub. Локальна версія пов’язана з remote для push і pull.
- **Staging**: підготовка файлів до commit. Команда `git add` додає файли до індексу для наступного commit.
- **Push**: надсилання локальних змін до remote, щоб інші могли отримати оновлений код.
- **Pull**: отримання змін із remote для оновлення локальної копії.
- **Origin**: назва remote за замовчуванням при першому підключенні локального repo до віддаленого; зазвичай це URL проєкту на GitHub.
